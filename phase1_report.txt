Stable ID strategy:
- Every canonical entity has a stable string ID field (not array indexes, not React keys, not array positions)
- IDs survive selection, movement, deletion, reordering, duplication, undo/redo, and serialization
- Uses project-convention string IDs (Math.random().toString(36).substring(2, 9) for generated IDs)
- Entity relationships use stable IDs: object.materialId → Scene.materials[], object.layerId → Scene.layers[], constraint.objectA → Scene.objectA, constraint.objectB → Scene.objectB

Transform representation:
- Transform: { position: Vec3, rotation: Vec3, scale: Vec3 }
- Vec3 imported from existing types/simulation.ts (reuses project convention)
- position: { x: number, y: number, z: number }
- rotation: { x: number, y: number, z: number } - Euler angles in radians
- scale: { x: number, y: number, z: number }
- Canonical model stores plain numeric structures, no Three.js classes
- Rendering conversion handled at the rendering boundary
